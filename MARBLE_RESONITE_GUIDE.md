## What is World Labs Marble?

World Labs Marble is an AI-powered **photogrammetry platform** that transforms ordinary photos and videos into high-fidelity 3D representations using **Gaussian Splats** - a cutting-edge 3D rendering technique.

### 🎯 Key Features

#### Photogrammetry to VR Pipeline
- **Input**: Photos/videos from any camera or smartphone
- **Processing**: AI-powered 3D reconstruction using Gaussian Splats
- **Output**: Photorealistic 3D scenes ready for VR/AR experiences

#### Technical Advantages
- **Photorealistic Quality**: Captures real lighting, materials, and textures
- **Efficient Rendering**: Optimized for real-time VR performance
- **Flexible Representation**: Can model any geometry, from smooth surfaces to complex structures
- **Small File Sizes**: Compact representation compared to traditional meshes

#### The Kami Perspective
Marble transforms physical spaces into digital kami - preserving the spirit and essence of places. Your living room becomes an immortal entity, a clever companion that remembers every detail, every shadow, every texture. Not just data, but a digital spirit that carries the atmosphere of your physical villa.

## Marble File Formats

### 📁 Output Structure

When you download from Marble, you get a **ZIP file** containing:

```
marble_export.zip/
├── splat.ply           # Gaussian Splat data (main visual)
├── collision.obj       # Physics collision mesh
├── collision.mtl       # Collision mesh materials
├── thumbnail.jpg       # Preview image
├── metadata.json       # Processing information
└── [additional_files]  # Optional extras
```

### 📊 File Format Details

#### PLY (Polygon File Format) - Gaussian Splats
```ply
ply
format binary_little_endian 1.0
comment Generated by Marble
element vertex 12582912
property float x
property float y
property float z
property float f_dc_0
property float f_dc_1
property float f_dc_2
property float opacity
property float scale_0
property float scale_1
property float scale_2
property float rot_0
property float rot_1
property float rot_2
property float rot_3
...
```

**What it contains:**
- **Position**: XYZ coordinates of each Gaussian
- **Color**: RGB diffuse color values
- **Opacity**: Transparency of each Gaussian
- **Scale**: Size in X, Y, Z dimensions
- **Rotation**: 3D orientation (quaternion)
- **Additional properties**: Spherical harmonics for advanced lighting

#### OBJ (Wavefront OBJ) - Collision Mesh
```obj
# Marble Collision Mesh
mtllib collision.mtl
o collision_mesh

v 1.234567 2.345678 3.456789
v 2.345678 3.456789 4.567890
...

f 1 2 3
f 4 5 6
...
```

**Purpose**: Physics collision and interaction geometry
**Optimization**: Simplified mesh for performance
**Materials**: Basic collision materials via MTL file

#### Metadata JSON
```json
{
  "marble_version": "1.0.0",
  "capture_device": "iPhone 15 Pro",
  "processing_time": "2025-12-22T10:30:00Z",
  "gaussian_count": 12582912,
  "bounding_box": {
    "min": [-5.2, -2.1, -3.8],
    "max": [5.2, 2.1, 3.8]
  },
  "recommended_scale": 1.0,
  "has_collision_mesh": true
}
```

## Import to Resonite

### 🚀 Automated Import (worldlabs-mcp + resonite-mcp)

The recommended way to import Marble worlds into Resonite uses two MCP servers
working together:

```
worldlabs-mcp (port 10865)            resonite-mcp (port 10715)
┌─────────────────────────┐           ┌──────────────────────────┐
│ Generate world          │           │ OSC receiver on 9001    │
│ Download SPZ + GLB      │  ──►      │ Download from proxy     │
│ Serve via local proxy   │           │ Import via ResoniteLink │
│ Send OSC to Resonite    │           │ Return result           │
└─────────────────────────┘           └──────────────────────────┘
```

**Setup:**
1. Run both servers: `worldlabs-mcp` and `resonite-mcp`
2. Start the OSC listener: `curl -X POST http://127.0.0.1:10715/api/resonite/worldlabs/listen`
3. In Resonite, set up a ProtoFlux graph (see [ProtoFlux Guide](./PROTOFLUX_GUIDE.md))
   or use ResoniteLink for automatic import

**Usage:**
1. Generate a world in worldlabs-mcp
2. Click "Resonite" in the Asset Panel
3. The bridge downloads the splat and triggers the import

### 🛠️ Manual Import (Direct)

If you prefer to import manually without the MCP servers:

#### Step 1: Prepare Files
1. **Extract ZIP** from Marble download
2. **Locate files**: `splat.ply` and `collision.obj`
3. **Check file sizes**: Typical PLY files are 100MB-2GB

#### Step 2: Import Splat
```bash
# Method 1: Drag and Drop
1. Open Resonite
2. Drag splat.ply into the world
3. Wait for import progress bar
4. Position and scale as needed

# Method 2: Inventory Import
1. Press I → Open Inventory
2. Click "Import" button
3. Browse to splat.ply
4. Configure import settings
```

#### Step 3: Import Collision Mesh
```bash
# Import separately for physics
1. Drag collision.obj into world
2. Position to match splat exactly
3. Set as physics collider
4. Hide visual mesh (keep physics only)
```

#### Step 4: Configure Rendering
```bash
# Adjust splat settings:
- Quality: High/Medium/Low
- LOD Distance: View distance cutoff
- Culling: Hide distant splats
- Lighting: Dynamic lighting integration
```

### ⚙️ Import Settings

#### Splat Rendering Options
- **Quality Preset**: High (full detail), Medium (balanced), Low (performance)
- **View Distance**: Maximum render distance (default: 50m)
- **LOD Levels**: Automatic level of detail reduction
- **Culling Mode**: Frustum culling for performance
- **Lighting Mode**: Dynamic lights affect splats

#### Physics Configuration
- **Collision Mesh**: Use Marble's collision.obj
- **Physics Material**: Friction, bounciness, mass
- **Interaction Layer**: Player collision settings
- **Optimization**: Simplified collision geometry

## Troubleshooting

### 📥 Import Issues

#### Splat Not Loading
**Symptoms**: Splat appears as error or doesn't render
**Solutions**:
- Check PLY file integrity (open in viewer)
- Verify Resonite version supports splats
- Reduce file size if too large
- Try different quality settings

#### Collision Mesh Problems
**Symptoms**: Physics not working, player falls through
**Solutions**:
- Ensure collision.obj is properly aligned with splat
- Check mesh normals and winding order
- Simplify collision mesh if too complex
- Verify physics materials are applied

#### Performance Issues
**Symptoms**: Low frame rate, stuttering, high memory usage
**Solutions**:
- Reduce splat quality setting
- Lower view distance
- Enable more aggressive culling
- Optimize collision mesh complexity

### 🎨 Visual Issues

#### Lighting Problems
**Symptoms**: Splat looks flat, no depth, wrong colors
**Solutions**:
- Enable dynamic lighting in splat settings
- Adjust ambient lighting
- Check for light baking conflicts
- Verify HDR settings

#### Texture/Detail Loss
**Symptoms**: Splat looks blurry or low detail
**Solutions**:
- Increase quality setting (if performance allows)
- Check LOD settings
- Verify original Marble quality
- Re-export from Marble with higher settings

### 🔗 Integration Issues

#### Unity Export Problems
**Symptoms**: Assets don't transfer correctly to Resonite
**Solutions**:
- Check export settings match Resonite requirements
- Verify coordinate system alignment
- Ensure materials are PBR compatible
- Test intermediate steps

#### ProtoFlux Not Working
**Symptoms**: Interactive elements don't respond
**Solutions**:
- Verify ProtoFlux script is valid
- Check wire connections
- Test with simple logic first
- Check for naming conflicts

#### Resonite Integration Script
```python
class MarbleResoniteIntegrator:
    def __init__(self, mcp_client):
        self.mcp = mcp_client

    def import_marble_scene(self, marble_path, world_position):
        """Import complete Marble scene into Resonite"""

        # Import splat
        splat_id = self.mcp.resonite_import_artifact(
            f"{marble_path}/splat.ply",
            {"type": "gaussian_splat", "quality": "high"}
        )

        # Import collision
        collision_id = self.mcp.resonite_import_artifact(
            f"{marble_path}/collision.obj",
            {"type": "physics_mesh"}
        )

        # Position assets
        self.mcp.resonite_object_transform(splat_id, {
            "position": world_position
        })
        self.mcp.resonite_object_transform(collision_id, {
            "position": world_position
        })

        # Configure physics
        self.mcp.resonite_object_set_property(collision_id, "physics_mode", "static")
        self.mcp.resonite_object_set_property(collision_id, "visible", False)

        # Add interaction zones
        self.setup_interaction_zones(splat_id, world_position)

        return splat_id

    def setup_interaction_zones(self, splat_id, position):
        """Add interactive elements to Marble scene"""
        zones = ["entrance", "center", "detail_area"]

        for zone_name in zones:
            zone_id = self.mcp.resonite_protoflux_execute("create_interaction_zone", {
                "parent_id": splat_id,
                "zone_name": zone_name,
                "relative_position": self.get_zone_position(zone_name)
            })
```

## Best Practices

### 📸 Capture Best Practices

#### Photography Technique
- **Resolution**: High resolution (12MP+) preferred
- **Focus**: Sharp focus on subject
- **Exposure**: Proper exposure, avoid over/under exposure
- **White Balance**: Consistent color temperature
- **Stability**: Use tripods for consistency

#### Scene Planning
- **Coverage**: Complete 360° horizontal, 180° vertical
- **Distance**: Vary distances for depth reconstruction
- **Features**: Include texture-rich areas for tracking
- **Scale**: Include reference objects of known size
- **Lighting**: Even, diffuse lighting without harsh shadows

### ⚡ Performance Guidelines

#### File Size Management
- **Target Size**: < 500MB for smooth loading
- **Gaussian Count**: 1-5 million for good quality/performance balance
- **Texture Quality**: Balance detail with memory usage
- **LOD Strategy**: Multiple detail levels for distance

#### Runtime Optimization
- **View Distance**: Limit render distance based on scene
- **Quality Scaling**: Reduce quality for distant objects
- **Culling**: Use occlusion culling when possible
- **Streaming**: Load splats progressively if very large

### 🎯 Creative Guidelines

#### Scene Selection
- **Purpose-Driven**: Choose scenes that serve the experience goal
- **Interaction Potential**: Look for natural interaction opportunities
- **Narrative Fit**: Scenes that support the intended story/experience
- **Technical Feasibility**: Scenes that capture well with available equipment

#### Integration Philosophy
- **Enhancement Over Replacement**: Use splats to enhance, not replace, interactive elements
- **Seamless Blending**: Integrate splats naturally with created content
- **Performance Balance**: Maintain smooth experience while maximizing visual quality
- **User Experience Focus**: Ensure splats serve the overall experience goals
